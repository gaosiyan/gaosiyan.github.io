# UE 上报 HARQ-ACK 的流程汇总
根据场景非为一下几张场景

1. FDD 非 CA 场景;
2. TDD 非 CA HARQ-ACK bundling 场景;
3. TDD 非 CA HARQ-ACK multiplexing 场景;
4. FDD CA 场景;
5. TDD CA 场景;
6. FDD-TDD CA 且 PCC 为 FDD 的场景;
7. FDD-TDD CA 且 PCC 为 TDD 的场景.

后文将分别针对上面描述的 7 种场景中的具体细节展开描述,具体包括:
- HARQ-ACK Bit 序列(即码本) $o_0^{ACK}, o_1^{ACK}, o_2^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$ 的生成,以及和\[载波\] codeword 的对应关系;
- PUCCH 资源的计算;
- PUCCH 资源冲突判决;
- PUSCH 信道编码.

:::warning
HARQ-ACK Bit 序列(即码本) $o_0^{ACK}, o_1^{ACK}, o_2^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$ 是一个二进制逻辑序列,即抽象的与具体实现无关的序列.
序列中的每个 bit 1 表示 ACK, 0 表示 NACK.逻辑序列中的 MSB(最高有效位),即这里的 $o_0^{ACK}$ 是编码器或者各种处理读取的的第一个 bit.一定要和具体实现的物理序列区分开;

codeword 和 TB 一般情况下是一一对应的,到但是 DCI2 系列中有交换字段.
:::

## FDD 非 CA 场景

### HARQ-ACK Bit 序列生成

在 PUSCH 或 PUCCH 信道传输时,$b(0)$代表 codeword 0, $b(1)$代表 codeword 1. FDD 非 CA 场景 bit 数由实际调度的 TB 个数确定,而不是由 TM 模式静态的决定的(这里的协议出处).

- 在 SR 周期和正 SR 冲突时使用 SR 的 PUCCH 资源发送 SR + HARQ-ACK(36.213 7.3.1);
- 否则使用 HARQ-ACK PUCCH 资源发送.

# HARQ-ACK Bit 序列的生成
## FDD 非 CA 场景 HARQ-ACK Bit 序列的生成
### 在 PUSCH 信道上反馈时的生成过程
HARQ-ACK Bit 序列被标记为 $o_0^{ACK}, o_1^{ACK}, o_2^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$. 

其中:
- 序列中的每一个元素(1 个 bit)代表一个 codeword 的 HARQ-ACK 结果;
- 1 表示 ACK, 0 表示 NACK;
- $O^{ACK}$ 表示序列的长度,对于支持双流的 TM 模式\{1,2,5,7,6\},$O^{ACK} = 2$(即使这些 TM 模式强制调度单流,$O^{ACK}$ 也是 2,两个 Bit 传输相同的 ACK/NACK 信息),否则 $O^{ACK} = 1$;
- $o_0^{ACK}$ 对应 codeword 0,$o_1^{ACK}$ 对应 codeword 1.

:::warning
codeword 和 TB 一般情况下是一一对应的,到但是 DCI2 系列中有交换字段.
:::

## TDD 非 CA 场景 HARQ-ACK Bit 序列的生成
### 在 PUSCH 信道上反馈时的生成过程
在 TDD 非 CA 场景下 HARQ 反馈可以配置为 HARQ-ACK bundling 或 HARQ-ACK multiplexing.

HARQ-ACK bundling 如下 <FigureRef id="HARQ-ACK bundling" /> 所示:

<Figure
  src="/img/content/a886d3d96ce6af6c7ddf70175e1b8e6a7acd773a.png"  
  title="HARQ-ACK bundling"
/>

一个反馈窗内的所有子帧的对应 codeword 时域与操作,最多生成 2 个 bit:
- $o_0^{ACK}$ 对应当前反馈窗内的所有下行子帧 codeword 0 的 ACK/NACK 结果;
- $o_1^{ACK}$ 对应当前反馈窗内的所有下行子帧 codeword 1 的 ACK/NACK 结果;
- 对于支持双流的 TM 模式\{1,2,5,7,6\},生成 2 bit,如果强制调度了单 TB,则没有调度的 TB 生成 NACK;
- 对于支持单流的 TM 模式,生成 1 bit.

HARQ-ACK multiplexing 如下 <FigureRef id="HARQ-ACK multiplexing" /> 所示:

<Figure
  src="/img/content/465be7142cb362ee75ddf21033468ff4c7ae6e31.png"  
  title="HARQ-ACK multiplexing"
/>

一个反馈窗内的同一个子帧两个 codeword 空域与操作,最多 4 个 bit:
- 配比 5 不支持配置 HARQ-ACK multiplexing 因为配比 5,子帧 2 要反馈 9 个子帧,需要 9 个 bit,而 HARQ-ACK multiplexing 最多反馈 4 个 bit;
- 当前配比对应上行子帧的 $M = 1$ 回退成 HARQ bundling;
- 对于支持双流的 TM 模式\{1,2,5,7,6\},如果强制调度了单 TB,则没有调度的 TB 生成 ACK;
- $o_0^{ACK} = V_{DAI}^{UL}$,即反馈窗内实际调度的 PDSCH 子帧数,因为 DCI 0/4 中的 $V_{DAI}^{UL}$ 是最全的包含有 PDCCH 的 PDSCH (SPS 周期上的 PDSCH,不含 PDCCh)和无 PDSCH 的 PDCCH (用于 DL SPS 释放的 PDCCH 不含 PDSCH)所有计数;
    - $o_0^{ACK}$ 代表反馈窗内第一个调度子帧,即 $V_{DAI}^{DL} = 1$ 的子帧,即根据 $V_{DAI}^{DL}$ 排序;
    - 如果有 SPS 周期上的 PDSCH,该子帧的 ACK/NACK 放在最后一个 bit,因为它没有 DCI 所以不存在 $V_{DAI}^{DL}$ 字段.

### 在 PUCCH 信道上反馈时的生成过程
基本过程和 PUSCH 类似,有两点重要区别:
1. HARQ-ACK bundling 时对于支持双流的 TM 模式\{1,2,5,7,6\},生成 2 bit,如果强制调度了单 TB,则没有调度的 TB 生成 DTX(PUSCH 是 NACK);
2. HARQ-ACK multiplexing 时 $o_0^{ACK} = M$ 即按照反馈窗长松排,没有调度的子帧生成 DTX.

## TDD HARQ-ACK 上报流程

本节是 36.213 7.3.2 节的内容的翻译

若 UE 配置非 CA,或者配置了 CA,并且 CA 所有服务小区的子帧配比相同则按 7.3.2.1 节流程上报 HARQ-ACK,否则参考 7.3.2.2 节(暂时不关注 7.3.2.2).

当仅需传输正调度请求(SR)时,UE 应使用 PUCCH 格式 1(见 36.211 5.4.1)

### 7.3.2.1 相同 UL/DL 配置的 TDD HARQ-ACK 上报流程

对于 TDD,当 UE 在 $n-k$ 子帧检测到 PDSCH 传输或者指示下行 SPS 释放的 PDCCH/EPDCCH 时,UE 需要在子帧 $n$ 发送对应的 HARQ-ACK 响应.
:::note
1. 有可能出现单独的 PDSCH,即 SPS 激活时没有对应 DCI 的 PDSCH;
2. 指示下行 SPS 释放的 PDCCH/EPDCCH,只有 PDCCH 无对应的 PDSCH.
:::

在 TDD 配置下,如果配置了 Format 3 反馈,服务小区中 Normal CP 特殊子帧配置 0 和 5 或 Extended CP 特殊子帧配置 0 和 4,该服务小区的特殊子帧应从 HARQ-ACK 码本大小确定中排除.

:::note
1. 上面描述的配置在特殊子帧上 DwPTS 字段极短(仅 3-4 OFDM 符号),无法承载有效 PDSCH 数据.所以不会在这些子帧调度 PDSCH;
2. 理论上来说可以发送 PDCCH,即可以发送指示下行 SPS 释放的 PDCCH/EPDCCH,但协议也规定不会在这些子帧发送指示下行 SPS 释放的 PDCCH/EPDCCH,所以 Format 3 的码本中可以不用预留.
:::
