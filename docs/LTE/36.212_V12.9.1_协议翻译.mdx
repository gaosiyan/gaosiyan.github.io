#### 5.2.2.6 控制信息的信道编码(未完成)

控制数据以信道质量信息(CQI 和[或] PMI),HARQ-ACK 以及 RI(秩指示,Rank Indication)的形式抵达编码单元.通过为控制信息的传输分配不同数量的编码符号,可实现不同的编码速率.当控制数据在 PUSCH 信道上传输时,HARQ-ACK,RI 以及信道质量信息 $o_0, o_1, o_2, ..., o_{O-1}$ 的信道编码是独立进行的.

:::note
上面的 $o_0, o_1, o_2, ..., o_{O-1}$ 比特流是控制数据比特流的统称.
:::

对于配置了 TDD 主小区的情况,HARQ-ACK 比特数的确定方法遵循 36.213 第 7.3 节的规定.

:::note
TDD 非 CA 小区,或者 TDD CA,以及 FDD-TDD CA 小区并且 PCC 是 TDD 的情况都参考 36.213 第 7.3.
:::

当 UE 发送 HARQ-ACK 比特或 RI 比特时,它应按下述方式确定用于 HARQ-ACK 或 RI 的每层编码调制符号数 $Q'$.

当承载 HARQ-ACK 比特或 RI 比特的 PUSCH 中仅传输一个 TB 时:

:::note
指上行 PUSCH 单 TB,即非 SUMIMO.
:::

$
Q' = min(\left \lceil \frac{O \cdot M_{SC}^{PUSCH-inital} \cdot N_{symb}^{PUSCH-inital} \cdot \beta _{offset}^{PUSCH} }{\sum_{r=0}^{C-1}K_r}\right \rceil,4 \cdot M_{SC}^{PUSCH})
$

其中:
- $O$ 是 HARQ-ACK 或 RI 的比特数;
- $M_{SC}^{PUSCH}$ 是当前子帧中为 TB 调度的 PUSCH 传输带宽,以子载波数量表示,参见 36.211;
:::note
$M_{SC}^{PUSCH} = Number Of RB \cdot 12$
:::

- $N_{symb}^{PUSCH-inital}$ 是指同一传输块在初始 PUSCH 传输(新传)时每子帧的 SC-FDMA 符号数,其计算公式为:$N_{symb}^{PUSCH-inital} = (2\cdot(N_{symb}^{UL}-1)-N_{SRS})$.其中:
    - $N_{symb}^{UL}$ 是每个 Slot 的上行符号,在 Normal CP 时为 7, Extended CP 时为 6,后面减 1 是去除导频符号;
    - 在以下情况 $N_{SRS} = 1$:
        - 若配置了一个上行链路小区的 UE 被设置为在同一子帧内发送初始传输的 PUSCH 和 SRS;
        - 若 UE 在同一服务小区的同一子帧内发送初始传输的 PUSCH 和 SRS;
        - 若初始传输的 PUSCH 资源分配与 36.211 章节 5.5.3 中定义的小区特定 SRS 子帧和带宽配置存在部分重叠;
        - 若同一服务小区中的初始传输子帧是 36.213 章节 8.2 中定义的 UE 特定 1 类 SRS 子帧;
        - 若同一服务小区中的初始传输子帧是 36.213 章节 8.2 中定义的 UE 特定 0 类 SRS 子帧,且 UE 配置了多个时间提前组(TAG).
    - 否则 $N_{SRS} = 0$.
- $M_{SC}^{PUSCH-initial},C,K_r$ 的值从同一传输块的初始 PDCCH 或 EPDCCH 中获取.如果同一传输块没有使用 DCI format 0 的初始 PDCCH 或 EPDCCH,则$M_{SC}^{PUSCH-initial},C,K_r$ 的值应通过以下方式确定:
    - 来自最新的半持续调度(Semi-Persistent Scheduling, SPS)指派 PDCCH 或 EPDCCH(当该传输块的初始 PUSCH 传输是半持续调度的);
    - 来自同一传输块的随机接入响应授权(Random Access Response Grant)(当 PUSCH 是由随机接入响应授权发起的).

当承载 HARQ-ACK 比特或 RI 比特的 PUSCH 中传输两个 TB 时:
:::note
PUSCH SUMIMO 的情况暂略.
:::

:::note
上面描述的 $Q'$ 即 HARQ-ACK 比特或 RI 比特占用的调制符号,即 RE 个数,最大占该 UE 带宽的 4 个 SC-OFDM 符号.
:::

对于 HARQ-ACK,$Q_{ACK} = Q_m \cdot Q'$,且 $\beta _{offset}^{PUSCH} = \beta _{offset}^{HARQ-ACK}$,其中 $Q_m$为对应 TB 的调制阶数\{2,4,6\}.$\beta _{offset}^{HARQ-ACK}$应根据 36.213 的规定,依据相应 PUSCH 传输的 TB 数量(单流还是双流)决定.

对于 RI,$Q_{RI} = Q_m \cdot Q'$,且 $\beta _{offset}^{PUSCH} = \beta _{offset}^{RI}$,其中 $Q_m$为对应 TB 的调制阶数\{2,4,6\}.$\beta _{offset}^{RI}$应根据 36.213 的规定,依据相应 PUSCH 传输的 TB 数量确定,当高层为该小区配置了两个上行功率控制子帧集时,还需根据相应 PUSCH 的上行功率控制子帧集确定.

对于 HARQ-ACK:
- ACK 被编码为二进制 1,NACK 被编码为二进制 0;
- 如果 HARQ-ACK 反馈包含 1 比特信息,即 $[o_0^{ACK}]$,则首先按照 Table 5.2.2.6-1 <FigureRef id="36.212 Table 5.2.2.6-1 1-bit HARQ-ACK 的编码" /> 进行编码;
- 如果 HARQ-ACK 反馈包含 2 比特信息,即 $[o_0^{ACK},o_1^{ACK}]$,其中 $o_0^{ACK}$ 对应 codeword 0 的 HARQ-ACK 比特, $o_1^{ACK}$ 对应 codeword 1 的 HARQ-ACK 比特,或者由于高层为 UE 配置的两个 DL 小区的 HARQ-ACK 比特聚合而形成 2 比特信息,或者对于 TDD 对应两个子帧的 2 比特信息,则首先按照表 5.2.2.6-2 <FigureRef id="36.212 Table 5.2.2.6-2 2-bit HARQ-ACK 的编码" />进行编码,其中$o_2^{ACK} = (o_0^{ACK}+o_1^{ACK})\;mod\;2$.

- 如果 HARQ-ACK 反馈信息由高层为 UE 配置的一个或多个下行小区所对应的 HARQ-ACK 比特聚合而形成 $3 \leq O^{ACK} \leq 11$ 比特(即  $o_0^{ACK} o_1^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$),则通过将比特序列  $o_0^{ACK} o_1^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$ 作为输入,送入第 5.2.2.6.4 节所述的信道编码块,得到一个编码比特序列 $\tilde{q}_0^{ACK} \tilde{q}_1^{ACK}, ..., \tilde{q}_{31}^{ACK}$.进而,通过对序列 $\tilde{q}_0^{ACK} \tilde{q}_1^{ACK}, ..., \tilde{q}_{31}^{ACK}$ 进行循环重复,获得比特序列 $q_0^{ACK}, q_1^{ACK}, q_2^{ACK}, ..., q_{Q_{ACK}-1}^{ACK}$,使得总比特序列长度等于 $Q_{ACK}$.

- 如果 HARQ-ACK 反馈信息由高层为 UE 配置的一个或多个下行小区所对应的 HARQ-ACK 比特聚合而形成 $11 < O^{ACK} \leq 21$ 比特(即 $o_0^{ACK} o_1^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$),则通过将比特序列 $o_0^{ACK} o_1^{ACK}, ..., o_{O^{ACK}-1}^{ACK}$ 作为输入,送入第 5.2.2.6.5 节所述的信道编码块,得到编码比特序列 $q_0^{ACK}, q_1^{ACK}, q_2^{ACK}, ..., q_{Q_{ACK}-1}^{ACK}$.

:::note
$Q_{ACK}$ 即 HARQ-ACK 软信息的长度,所占的 RE 个数乘以调制阶数.
:::

表 5.2.2.6-1 <FigureRef id="36.212 Table 5.2.2.6-1 1-bit HARQ-ACK 的编码" />和 5.2.2.6-2 <FigureRef id="36.212 Table 5.2.2.6-2 2-bit HARQ-ACK 的编码" />中的 x 和 y 是占位符,用于文献 36.211 中以最大化承载 HARQ-ACK 信息的调制符号的欧几里得距离的方式对 HARQ-ACK 比特进行加扰.

对于 FDD 或 TDD HARQ-ACK multiplexing,或者当一个或多个下行小区的聚合中至少包含一个使用 FDD 的小区和一个使用 TDD 的小区且 HARQ-ACK 信息由 1 或 2 比特组成时,比特序列 $q_0^{ACK}, q_1^{ACK}, q_2^{ACK}, \ldots, q_{Q_{ACK}-1}^{ACK}$ 是通过多个编码后的 HARQ-ACK 块的串联获得的,其中 $Q_{ACK}$ 是所有编码 HARQ-ACK 块的编码比特总数.最后一个编码 HARQ-ACK 块的串联可以是部分的,以使总比特序列长度等于 $Q_{ACK}$.

:::note
这里描述了三种场景:
1. FDD;
2. TDD HARQ-ACK multiplexing;
3. FDD-TDD CA 并且 2 Bit.

这三种情况直接循环拼接到 $Q_{ACK}$ 个 bit,最后一部分可能不完整. 问题是其它场景 2 个 bit 呢?
:::

对于 FDD,当 HARQ-ACK 由于多个 DL 小区的聚合而包含 2 比特或更多信息时,比特序列 $o[0], o[1], ..., o[O^{ACK}-1]$ 是通过以下伪代码所述方式将多个 DL 小区的 HARQ-ACK 比特进行串联拼接而成的:

```python
c = 0 # [0,cell_index] 区间循环,较低索引对应较低 RRC 配置索引的小区
j = 0 # HARQ-ACK bit index
N_cells_DL = higher_layers_configured_for_the_UE # 高层为该 UE 配置的下行激活载波数 $N_{cells}^{DL}$,,即载波索引 c in [0,$N_{cells}^{DL}-1],且 PCC c = 0

while c < N_cells_DL:
    if transmission_mode in [1,2,5,6,7]: # 当前载波的传输模式不支持空分复用时
        o_ACK[c][j] = HARQ_ACK_bit_of_this_cell # o_ACK[c][j] 即 $o_{c,j}^{ACK}$
        j = j + 1
    else:                                # 当前载波的传输模式支持空分复用时
        o_ACK[c][j] = HARQ_ACK_bit_of_this_cell_first_codeword  # 低 bit 关联到第一个 codeword
        j = j + 1
        o_ACK[c][j] = HARQ_ACK_bit_of_this_cell_second_codeword # 高 bit 关联到第二个 codeword
        j = j + 1
    c = c + 1
```

:::note
上面描述的是纯 FDD CA 小区,注意不含非 CA,下面描述的是 FDD-TDD 组 CA,即 PCC 是 FDD,且至少有一个 SCC 是 TDD 的情况.

:::

对于包含一个使用 FDD 的主小区及至少一个使用 TDD 的辅小区的多个 DL 小区的聚合,比特序列 $ o_0^{ACK} o_1^{ACK}, ..., o_{O_{ACK}-1}^{ACK} $ 是一个或多个 DL 小区的 HARQ-ACK 比特级联后的结果.定义 $ N_{cells}^{DL} $ 为高层为 UE 配置的小区数量,并定义 $ B_c^{DL}$ 为 UE 需要在 UL 子帧 n 中为第$c$个服务小区反馈 HARQ-ACK 比特的子帧数.对于使用 TDD 的小区,如果 UE 配置了高层参数 `eimta-HARQ-ReferenceConfig`,则子帧由  `DL-reference UL/DL configuration` 决定,否则由 `UL/DL configuration` 配置决定.对于使用 TDD 的小区,如果该小区中的子帧 $n-4$ 是下行子帧,或者是具有特殊子帧配置 1/2/3/4/6/7/8/9(常规下行 CP)或特殊子帧配置 1/2/3/5/6/7(扩展下行 CP)的特殊子帧,则 $B_c^{DL} = 1$,否则 $B_c^{DL} = 0$.对于使用 FDD 的小区,$B_c^{DL} = 1$.

比特序列 $o_0^{ACK} o_1^{ACK},...,o_{O^{ACK}-1}^{ACK}$ 按照以下伪代码生成:

```python
c = 0 # [0,cell_index] 区间循环,较低索引对应较低 RRC 配置索引的小区
j = 0 # HARQ-ACK bit index

while c < N_cells_DL:
    if B_DL[c] == 1:  # 对应 c 小区的 B_c^{DL},即反馈窗内单子帧的情况
        if transmission_mode in [1,2,5,6,7]: # 当前载波的传输模式不支持空分复用时
            o_ACK[c][j] = HARQ_ACK_bit_of_this_cell # o_ACK[c][j] 即 $o_{c,j}^{ACK}$
            j = j + 1
        else:                                # 当前载波的传输模式支持空分复用时
            o_ACK[c][j] = HARQ_ACK_bit_of_this_cell_first_codeword   # 低 bit 关联到第一个 codeword
            j = j + 1
            o_ACK[c][j] = HARQ_ACK_bit_of_this_cell_second_codeword  # 高 bit 关联到第二个 codeword
            j = j + 1
    c = c + 1       

```
:::note
eIMTA 是 R12 中引入的,该功能可以在预设值的几个 TDD 帧配比中利用 DCI 进行快速的切换.可以简单理解为 LTE 中的灵活帧配比.一般情况下不会配置.
:::

对于配置了 TDD 主小区,且 HARQ-ACK 针对一个或多个下行载波聚合,同时 UE 配置了 PUCCH format 3 的情况, 比特序列 $o_0^{ACK} o_1^{ACK},...,o_{O^{ACK}-1}^{ACK}$ 是通过连接高层配置的一个或多个下行载波及多个子帧的 HARQ-ACK 比特而形成的,具体定义见 36.213.
$N_{cells}^{DL}$ 为高层为 UE 配置的小区数量,$B_c^{DL}$为 UE 需要反馈 HARQ-ACK 比特的子帧数量,其定义参见 36.213 第 7.3 节.

如果 UE 配置了 PUCCH format 3,其需要传送的 HARQ-ACK 比特数量按以下方式计算:

```python
k = 0 # HARQ-ACK bit index
c = 0 # [0,cell_index] 区间循环,较低索引对应较低 RRC 配置索引的小区

while c < N_cells_DL:
    l = 0
    while l < B_DL[c]:  # 反馈子帧循环
        if transmission_mode in [1,2,5,6,7]: # 当前载波的传输模式不支持空分复用时
            k = k + 1
        else:
            k = k + 2
        l = l + 1
    c = c + 1
```
:::note
上面描述的场景主要是计算 $k$,代表实际原始的 ACK bit 数目, 按照 TM 模式计算而不是实际调度的 TB,每个 TB 一个 Bit.
:::

如果当 UE 所有配置服务小区均使用 TDD 时且 $k \le 20$,或当至少一个配置服务小区使用 FDD 且主小区为 TDD 且 $k \le 21$ 时,则 HARQ-ACK 比特的复用按以下伪代码执行:

```python
c = 0 # [0,cell_index] 区间循环,较低索引对应较低 RRC 配置索引的小区
j = 0 # HARQ-ACK bit index

while c < N_cells_DL:
    l = 0
    while l < B_DL[c]:  # 反馈子帧循环
        if transmission_mode in [1,2,5,6,7]: # 当前载波的传输模式不支持空分复用时
            o_ACK[j] = o_ACK[c][l] #   \tilde{o}_j^{ACK} = o_{c,j}^{ACK}
            j = j + 1
        else:
            o_ACK[j],o_ACK[j+1] = o_ACK[c][2l],o_ACK[c][2l+1]
            j = j + 2
        l = l + 1
    c = c + 1
```
:::note
上面描述的场景是用 $o_{c,j}^{ACK}$ (伪码中的 `o_ACK[c][l]`)得到 $\tilde{o}_j^{ACK}$ (伪码中的 `o_ACK[j]`),转换前后没有进行压缩即没有 spatial bundling 操作,转换前后是一一对应的关系.
:::

如果当 UE 所有配置服务小区均使用 TDD 时且 $k > 20$,或者当至少一个配置服务小区使用 FDD 且主小区为 TDD 时且 $k > 21$,则对所有小区中的所有子帧应用空间绑定(spatial bundling),并按下述伪代码进行 HARQ-ACK 比特的复用:

```python
c = 0 # [0,cell_index] 区间循环,较低索引对应较低 RRC 配置索引的小区
j = 0 # HARQ-ACK bit index

while c < N_cells_DL:
    l = 0
    while l < B_DL[c]:  # 反馈子帧循环
        if transmission_mode in [1,2,5,6,7]: # 当前载波的传输模式不支持空分复用时
            o_ACK[j] = o_ACK[c][l] #   \tilde{o}_j^{ACK} = o_{c,j}^{ACK}
            j = j + 1
        else:
            o_ACK[j] = o_ACK[c][l] #   这里的 o_ACK[c][l] 对该小区第一个和第二个码字所对应的 HARQ-ACK 比特进行如 36.213 第 7.3 节所定义的二进制与操作
            j = j + 1
        l = l + 1
    c = c + 1
```

若 $o^{ACK} \leq 11$,则通过设置 $o_i^{ACK} = \tilde{o}_i^{ACK}$ 来获得比特序列 $o_0^{ACK}, o_1^{ACK}, ...,o_{o^{ACK}-1}^{ACK}$.
若 $ 11 < o^{ACK} \leq 21$,则按以下方式获得比特序列  $o_0^{ACK}, o_1^{ACK}, ..., o_{o^{ACK}-1}^{ACK}$,若 $ i $ 为偶数,则设置 $ o_{\lfloor i/2 \rfloor}^{ACK} = \tilde{o}_i^{ACK} $;若 $i$ 为奇数,则设置 $ o_{\lfloor o^{ACK}/2 \rfloor + \lfloor (i-1)/2 \rfloor}^{ACK} = \tilde{o}_i^{ACK} $.

对于 TDD 主小区,且 HARQ-ACK 用于两个下行载波的聚合,同时 UE 配置了采用信道选择的 PUCCH format 1b 的情况,则按照 36.213 第 7.3 节所述方式获得比特序列 $o_0^{ACK}, o_1^{ACK}, ..., o_{o^{ACK}-1}^{ACK}$.

对于 TDD HARQ-ACK bundling,通过级联多个已编码的 HARQ-ACK 块获得一个比特序列 $\widetilde{q}_0^{ACK},\widetilde{q}_1^{ACK},\widetilde{q}_2^{ACK},...,\widetilde{q}_{Q_{ACK}-1}^{ACK}$,其中 $Q_{ACK}$ 是所有已编码 HARQ-ACK 块的总编码比特数. 最后一个已编码 HARQ-ACK 块的级联可能是部分的,以使总比特序列长度等于 $Q_{ACK}$. 随后查表 Table 5.2.2.6-A <FigureRef id="36.212 Table 5.2.2.6-A 用于 TDD HARQ-ACK bundling 的加扰序列选择" /> 根据索引 $i=(N_{bundled}-1)\text{ mod }4$ 选择一个加扰序列 $[w_0^{ACK}\text{ }w_1^{ACK}\text{ }w_2^{ACK}\text{ }w_3^{ACK}]$,其中 $N_{bundled}$ 由 36.213 第 7.3 节的规定确定.接着,通过设置 $m = 1$(如果 HARQ-ACK 由 1 比特组成) 和  $m = 3$(如果 HARQ-ACK 由 2 比特组成),并如下所述对序列 $\widetilde{q}_0^{ACK},\widetilde{q}_1^{ACK},\widetilde{q}_2^{ACK},...,\widetilde{q}_{Q_{ACK}-1}^{ACK}$ 进行加扰,来生成比特序列 ${q}_0^{ACK},{q}_1^{ACK},{q}_2^{ACK},...,{q}_{Q_{ACK}-1}^{ACK}$:

$$
\begin{aligned}
&i = 0\\
&k = 0\\

&while\;i < Q_{ACK} \\
&\qquad if\;\widetilde{q}_i^{ACK} = y\;//占位重复比特\\
&\qquad\qquad {q}_i^{ACK} = (\widetilde{q}_{i-1}^{ACK}+w_{\lfloor k/m \rfloor}^{ACK})\;mod\;2\\
&\qquad\qquad k = (k+1)\;mod\;4m\\
&\qquad else\\
&\qquad\qquad if\;\widetilde{q}_i^{ACK} = x\;//占位重复比特\\
&\qquad\qquad\qquad {q}_i^{ACK} = \widetilde{q}_{i}^{ACK}\\
&\qquad\qquad else\\
&\qquad\qquad\qquad {q}_i^{ACK} = (\widetilde{q}_{i}^{ACK}+w_{\lfloor k/m \rfloor}^{ACK})\;mod\;2\\
&\qquad\qquad\qquad  k = (k+1)\;mod\;4m\\
&\qquad end\;if\\
&\qquad i = i+1\\
&end\; while
&\end{aligned}
$$
