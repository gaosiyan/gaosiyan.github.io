## TDD HARQ-ACK 上报流程

本节是 36.213 7.3.2 节的内容的翻译

若 UE 配置非 CA,或者配置了 CA,并且 CA 所有服务小区的子帧配比相同则按 7.3.2.1 节流程上报 HARQ-ACK,否则参考 7.3.2.2 节(暂时不关注 7.3.2.2).

当仅需传输正调度请求(SR)时,UE 应使用 PUCCH 格式 1(见 36.211 5.4.1)

### 7.3.2.1 相同 UL/DL 配置的 TDD HARQ-ACK 上报流程

对于 TDD,当 UE 在 $n-k$ 子帧检测到 PDSCH 传输或者指示下行 SPS 释放的 PDCCH/EPDCCH 时,UE 需要在子帧 $n$ 发送对应的 HARQ-ACK 响应.
:::note
1. 有可能出现单独的 PDSCH,即 SPS 激活时没有对应 DCI 的 PDSCH;
2. 指示下行 SPS 释放的 PDCCH/EPDCCH,只有 PDCCH 无对应的 PDSCH.
:::

在 TDD 配置下,如果配置了 Format 3 反馈,服务小区中 Normal CP 特殊子帧配置 0 和 5 或 Extended CP 特殊子帧配置 0 和 4,该服务小区的特殊子帧应从 HARQ-ACK 码本大小确定中排除.

:::note
1. 上面描述的配置在特殊子帧上 DwPTS 字段极短(仅 3-4 OFDM 符号),无法承载有效 PDSCH 数据.所以不会在这些子帧调度 PDSCH;
2. 理论上来说可以发送 PDCCH,即可以发送指示下行 SPS 释放的 PDCCH/EPDCCH,但协议也规定不会在这些子帧发送指示下行 SPS 释放的 PDCCH/EPDCCH,所以 Format 3 的码本中可以不用预留.
:::
