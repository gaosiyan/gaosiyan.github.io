### 7.3.1 FDD HARQ-ACK 上报流程

对于采用 PUCCH format 1a/1b 传输的 FDD,当 HARQ-ACK 和 SR 在同一子帧中传输时,UE 应在负 SR 传输时在其分配的 HARQ-ACK PUCCH format 1a/1b 资源上传输 HARQ-ACK,并在正 SR 传输时在其分配的 SR PUCCH 资源上传输 HARQ-ACK.

对于采用带信道选择的 PUCCH format 1b 的 FDD,当 HARQ-ACK 和 SR 在同一子帧中传输时,UE 应在负 SR 传输时在其分配的带信道选择的 HARQ-ACK PUCCH 资源上(如子条款 10.1.2.2.1 所定义)传输 HARQ-ACK,并在正 SR 传输时在其分配的 SR PUCCH 资源上为每个服务小区传输一个 HARQ-ACK 比特,具体如下:

- 如果在一个服务小区上仅检测到一个 TB 或一个指示下行 SPS 释放的 PDCCH/EPDCCH,则该服务小区的 HARQ-ACK 比特是对应于该传输块或指示下行 SPS 释放的 PDCCH/EPDCCH 的 HARQ-ACK 比特;

- 如果在一个服务小区上接收到两个 TB,则该服务小区的 HARQ-ACK 比特是通过对对应于传输块的 HARQ-ACK 比特进行空间捆绑生成的;

- 如果对于一个服务小区,既未检测到需要提供 HARQ-ACK 响应的 PDSCH 传输,也未检测到指示下行 SPS 释放的 PDCCH/EPDCCH,则该服务小区的 HARQ-ACK 比特设置为 NACK;

且主小区和辅小区的 HARQ-ACK 比特分别映射到 $b(0)$ 和 $b(1)$,其中 $b(0)$ 和 $b(1)$ 在 36.211 的子条款 5.4.1 中规定.

对于 FDD,当 HARQ-ACK 的 PUCCH format 3 传输与高层为 UE 配置的用于传输 SR 的子帧重合时,UE 应按照 36.212 的子条款 5.2.3.1 中的定义在 HARQ-ACK PUCCH 资源上复用 HARQ-ACK 和 SR 比特,除非 HARQ-ACK 对应于仅在 PCC 上的 PDSCH 传输或仅在 PCC 上指示下行 SPS 释放的 PDCCH/EPDCCH,在这种情况下,SR 应按照采用 PUCCH format 1a/1b 的 FDD 方式进行传输.

对于 FDD 和 PUSCH 传输,如果 UE 在子帧 $ n-4 $ 中没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH,则 UE 不应在子帧 $ n $ 的 PUSCH 上传输 HARQ-ACK.

当仅传输正 SR 时,UE 应使用 36.211 的子条款 5.4.1 中定义的 SR 资源的 PUCCH format 1.

#### 7.3.2.1 相同帧配比的 TDD HARQ-ACK 上报流程(未完成)

对于 TDD,UE 应在检测到子帧 $ n - k $ 内(其中 $ k \in K $ 且 $K$ 在表 10.1.3.1-1<FigureRef id="36.213 Table 10.1.3.1-1" /> 中定义)针对该 UE 且需要提供 HARQ-ACK 响应的 PDSCH 传输或指示下行 SPS 释放(在子条款 9.2 中定义)的 PDCCH/EPDCCH 时,在 UL 子帧 $ n $ 中传输 HARQ-ACK 响应.

对于 TDD,当配置了 PUCCH format 3 用于传输 HARQ-ACK 时,对于服务小区中采用正常下行 CP 的特殊子帧配置 0 和 5 或采用扩展下行 CP 的配置 0 和 4(见表 36.211 4.2-1),该服务小区的特殊子帧被排除在 HARQ-ACK 码本大小确定之外.在这种情况下,如果服务小区是主小区,则该特殊子帧中没有指示下行 SPS 释放的 PDCCH/EPDCCH.

:::note
正常下行 CP 的特殊子帧配置 0 和 5 或采用扩展下行 CP 的配置 0 和 4 下对应特殊子帧的 DwPTS 太短,不能用于发送 PDSCH, 并且规定 PDCCH 上也不能用于发送指示下行 SPS 释放的 PDCCH/EPDCCH,所以对应的码本中可以去除,注意只有 PCC 支持 SPS. 那么 format 1bcs 呢?
:::

对于 TDD 上下行配置 1-6 且配置了一个服务小区的情况,如果 UE 未配置 PUCCH format 3,则在子帧 $n - k'$ 中(其中 $k'$ 在表 7.3-Y 中定义<FigureRef id="36.213 Table 7.3-Y" />)由 UE 根据表 7.3-X <FigureRef id="36.213 Table 7.3-X" /> 检测到的 DCI format 0/4 中的下行分配索引 (DAI) 值 $V_{DAI}^{UL}$,表示在所有子帧 $ n - k $(其中 $k \in K$)内,具有 PDSCH 传输以及具有指示下行 SPS 释放的 PDCCH/EPDCCH 且针对相应 UE 的子帧总数.值 $V_{DAI}^{UL}$ 包括所有子帧 $n - k$ 内具有和不具有相应 PDCCH/EPDCCH 的所有 PDSCH 传输.如果既没有针对 UE 的 PDSCH 传输,也没有指示下行 SPS 资源释放的 PDCCH/EPDCCH,则 UE 可以预期,如果传输了 DCI format 0/4 中的 DAI 值 $V_{DAI}^{UL}$,则该值被设置为 4.

:::note
1. $V_{DAI}^{UL}$ 是最全的,由于是在 DCI format 0/4 上传输的,$n - k'$ 即对应 $n$ 的 DCI format 0/4 检测时间,所以肯定是 PUSCH 信道反馈;
2. 最初的 Release 8 协议支持配置 0-6,上下行配置 0 上行子帧多于下行子帧,所以和 FDD 类似,不存在 DAI 的概念;
3. 这里为什么强"调配置了一个服务小区 + 没有配置 PUCCH format3" 是否等价于非 CA 场景?
:::

对于 TDD 上下行配置 1-6 且配置了多个服务小区的 UE,或者对于 TDD 上下行配置 1-6 且配置了一个服务小区和 PUCCH format 3 的 UE,一个值 $W_{DAI}^{UL}$ 由子帧 $n - k'$ 中(其中 $ k' $ 在表 7.3-Y <FigureRef id="36.213 Table 7.3-Y" /> 中定义) DCI format 0/4 中的下行分配索引 (DAI) 根据表 7.3-Z <FigureRef id="36.213 Table 7.3-Z" /> 确定.如果既没有针对 UE 的 PDSCH 传输,也没有指示下行 SPS 资源释放的 PDCCH/EPDCCH,则 UE 可以预期,如果传输了 DCI format 0/4 中的 DAI,则 $W_{DAI}^{UL}$ 的值被设置为 4.

:::note
1. 非 CA 的 UE 也可以配置也可以使用 PUCCH format 3,FDD 和 TDD 下具体如何使用?
2. $V_{DAI}^{UL}$ 和 $W_{DAI}^{UL}$ 是 DCI format 0/4 中的相同字段在不同场景下的解释.
  - 单小区且未配置 PUCCH Format 3 的情况下,这个字段才被解读为 $V_{DAI}^{UL}$,否则都被解释成 $W_{DAI}^{UL}$;
  - 在 CA 场景下假设多个载波同时有 DCI format 0/4,那么 $W_{DAI}^{UL}$ 是相同的, $W_{DAI}^{UL} = MAX(V_{DAI,c}^{UL})$.
:::

对于 TDD 上下行配置 1-6,DCI format 1/1A/1B/1D/2/2A/2B/2C/2D 中的 DAI 值表示在每个配置的服务小区的子帧 $n - k$(其中 $k \in K$)内,直至当前子帧为止的,分配了 PDSCH 传输的 PDCCH/EPDCCH 以及指示下行 SPS 释放的 PDCCH/EPDCCH 的累积数量,并且应逐子帧更新.将 $V_{DAI,c}^{DL}$ 表示为由 UE 在服务小区 $c$ 的子帧 $n - k_m$ 中根据表 7.3-X<FigureRef id="36.213 Table 7.3-X" /> 检测到的,带有 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D 的 PDCCH/EPDCCH 中的 DAI 值,其中 $k_m$ 是集合 K(在表 10.1.3.1-1<FigureRef id="36.213 Table 10.1.3.1-1" /> 中定义)中的最小值,使得 UE 检测到一个 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D.当配置了一个服务小区时,$V_{DAI,c}^{DL}$ 中的下标 $c$ 可以省略.

:::note
1. $V_{DAI,c}^{DL}$ 是下行 DCI 中带的一个累加值,由于是在下行 DCI 中携带的,所以只能对有 DCI 的 PDSCH 进行编号;
2. 表 10.1.3.1-1<FigureRef id="36.213 Table 10.1.3.1-1" /> 中对应 $K$ 集合中的最小 $k_m$ 是最近的一个下行子帧.
:::

对于所有 TDD 上下行配置,将 $U_{DAI,c}$ 表示为在服务小区 $c$ 的子帧 $n - k$(其中 $k \in K$)内由 UE 检测到的,分配了 PDSCH 传输的 PDCCH/EPDCCH 以及指示下行 SPS 释放的 PDCCH/EPDCCH 的总数.当配置了一个服务小区时,$U_{DAI,c}$ 中的下标 $c$ 可以省略.将 $N_{SPS}$(可以是 0 或 1)表示为在子帧 $n - k$(其中 $k \in K$)内没有相应 PDCCH/EPDCCH 的 PDSCH 传输的数量.

:::note
$U_{DAI,c}$ 是 UE 侧截至当前看到的需要反馈的子帧计数,即在整个反馈窗没有漏检的情况下:
- 如果在 PUSCH 上反馈,那么截至子帧 $n$,$U_{DAI,c}　= V_{DAI,c}^{UL} \text{ or } W_{DAI}^{UL}$;
- 如果在 PUCCH 上反馈,那么截至子帧 $n$,$U_{DAI,c}　= V_{DAI,c}^{DL} + N_{SPS}$.
:::

对于 TDD HARQ-ACK bundling 或 HARQ-ACK multiplexing 以及 $M = 1$ 的子帧 $n$,UE 应通过对所有相应的 $U_{DAI} + N_{SPS}$ 个独立 PDSCH 传输 HARQ-ACK 以及为响应接收到的指示下行 SPS 释放的 PDCCH/EPDCCH 而发出的独立 ACK,在每个码字上跨与单个 UL 子帧相关联的 $M$ 个下行的和特殊的子帧执行逻辑 AND 操作,来生成一个或两个 HARQ-ACK 比特,其中 $M$ 是表 10.1.3.1-1<FigureRef id="36.213 Table 10.1.3.1-1" /> 中定义的集合 $K$ 中的元素数量.UE 应检测是否至少漏检了一个下行分配,并且对于 UE 在 PUSCH 上传输的情况,UE 还应确定参数 $N_{\text{bundled}}$.

    - 对于 TDD 上下行配置 0,如果 UE 在子帧 $ n - k $(其中 $ k \in K $)内检测到具有或不具有相应 PDCCH/EPDCCH 的 PDSCH 传输,或检测到指示下行 SPS 释放的 PDCCH,则 $ N_{\text{bundled}} $ 应为 1.如果 UE 在子帧 $ n - k $(其中 $ k \in K $)内没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH,则 UE 不应在 PUSCH 上传输 HARQ-ACK.

    - 对于 UE 未在子帧 $ n $ 中的 PUSCH 上传输且 TDD 上下行配置为 1-6 的情况,如果
    $ U_{DAI} > 0 \quad \text{and} \quad V_{DAI}^{DL} \neq (U_{DAI} - 1) \mod 4 + 1, $
    则 UE 检测到至少漏检了一个下行分配.

    - 对于 UE 在 PUSCH 上传输且 PUSCH 传输是基于检测到的,针对该 UE 的带有 DCI format 0/4 的 PDCCH/EPDCCH 进行调整的情况,且 TDD 上下行配置为 1-6,如果
    $ V_{DAI}^{UL} \neq (U_{DAI} + N_{SPS} - 1) \mod 4 + 1 $
    则 UE 检测到至少漏检了一个下行分配,并且 UE 应为所有码字生成 NACK,其中
    $ N_{\text{bundled}} $
    由 UE 确定为
    $ N_{\text{bundled}} = V_{DAI}^{UL} + 2. $
    如果 UE 未检测到任何下行分配遗漏,
    $ N_{\text{bundled}} $
    由 UE 确定为
    $ N_{\text{bundled}} = V_{DAI}^{UL}. $
    如果
    $ U_{DAI} + N_{SPS} = 0 \quad \text{and} \quad V_{DAI}^{UL} = 4 $
    则 UE 不应传输 HARQ-ACK.

    - 对于 UE 在 PUSCH 上传输,且 PUSCH 传输不是基于检测到的,针对该 UE 的带有 DCI format 0/4 的 PDCCH/EPDCCH 的情况,且 TDD 上下行配置为 1-6,如果
    $ U_{DAI} > 0 \quad \text{and} \quad V_{DAI}^{DL} \neq (U_{DAI} - 1) \mod 4 + 1, $
    则 UE 检测到至少漏检了一个下行分配,并且 UE 应为所有码字生成 NACK.UE 确定
    $ N_{\text{bundled}} = (U_{DAI} + N_{SPS}) $
    作为已分配子帧的数量.如果
    $ U_{DAI} + N_{SPS} = 0 $
    则 UE 不应传输 HARQ-ACK.

对于 TDD,当配置 PUCCH format 3 用于传输 HARQ-ACK 时,由 RRC 配置的第 c 个服务小区的 HARQ-ACK 反馈比特
$ O_{c,0}^{ACK} O_{c,1}^{ACK}, \ldots, O_{c,O_{c}}^{ACK} O_{c,1}^{ACK} $
按如下方式构造,其中 $ c \geq 0 $,
$ O_{c}^{ACK} = B_{c}^{DL} $
如果第 c 个服务小区中配置的传输模式支持一个传输块或应用了空间 HARQ-ACK 捆绑,否则
$ O_{c}^{ACK} = 2B_{c}^{DL} $
其中
$ B_{c}^{DL} $
是 UE 需要为第 c 个服务小区反馈 HARQ-ACK 比特的下行和特殊子帧的数量.

    - 对于 UE 在 PUCCH 上传输的情况,
    $ B_{c}^{DL} = M $
    其中
    $ M $
    是与子帧 $ n $ 相关联的集合 $ K $(在表 10.1.3.1-1 中定义)中的元素数量,并且集合 $ K $ 不包括具有正常下行 CP 的配置 0 和 5 或具有扩展下行 CP 的配置 0 和 4 的特殊子帧;否则
    $ B_{c}^{DL} = M - 1. $

    - 对于 TDD 上下行配置 0 或对于未基于检测到的带有 DCI format 0/4 的 PDCCH/EPDCCH 进行调整的 PUSCH 传输,UE 应假设
    $ B_{c}^{DL} = M $
    其中
    $ M $
    是与子帧 $ n $ 相关联的集合 $ K $(在表 10.1.3.1-1 中定义)中的元素数量,并且集合 $ K $ 不包括具有正常下行 CP 的配置 0 和 5 或具有扩展下行 CP 的配置 0 和 4 的特殊子帧;否则
    $ B_{c}^{DL} = M - 1. $
    如果 UE 在子帧 $ n - k $(其中 $ k \in K $)内没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH/EPDCCH,则 UE 不应在 PUSCH 上传输 HARQ-ACK.

    - 对于 TDD 上下行配置 {1, 2, 3, 4, 6} 以及基于检测到的带有 DCI format 0/4 的 PDCCH/EPDCCH 进行调整的 PUSCH 传输,UE 应假设
    $ B_{c}^{DL} = W_{DAI}^{UL}. $
    如果 UE 在子帧 $ n - k $(其中 $ k \in K $)内没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH/EPDCCH 且 $ W_{DAI}^{UL} = 4 $,则 UE 不应在 PUSCH 上传输 HARQ-ACK.

    - 对于 TDD 上下行配置 5 以及基于检测到的带有 DCI format $ 0/4 $ 的 PDCCH/EPDCCH 进行调整的 PUSCH 传输,UE 应假设
    $ B_c^{DL} = W_{DAI}^{UL} + 4 \left[ \left( U - W_{DAI}^{UL} \right) / 4 \right], $
    其中 $ U $ 表示所有配置的服务小区中 $ U_c $ 的最大值,$ U_c $ 是在第 $ c $ 个服务小区的子帧 $ n - k $($ k \in K $)内接收到的 PDSCH 和指示下行 SPS 释放的 PDCCH/EPDCCH 的总数.如果 UE 在子帧 $ n - k $(其中 $ k \in K $)内没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH/EPDCCH 且
    $ W_{DAI}^{UL} = 4 $
    则 UE 不应在 PUSCH 上传输 HARQ-ACK.

#### 7.3.2.2 不同帧配比的 TDD HARQ-ACK 上报流程(未完成)

对于一个配置的服务小区,在本子条款的后续部分中的 DL-reference UL/DL configuration 在子条款 10.2 中定义.

对于一个配置的服务小区,如果其 DL-reference UL/DL configuration 为 0,则 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D 中的 DAI(下行分配索引)不被使用.

:::note
这句话不是专门针对 CA 或者说 FDD+TDD CA 而言的,而是针对所有 TDD,因为配比 0 一个上行子帧最多反馈一个下行子帧,所以 DAI 没有什么意义.
:::

对于服务小区 $c$, UE 在应当在子帧 $n$ 反馈子帧 $n-k$ 其中($k\in K_c$) 检测到的 PDSCH 或指示下行 SPS 释放(定义于子条款 9.2)的 PDCCH/EPDCCH HARQ-ACK.
其中集合 $K_c$ 包含所有满足以下条件的 $k \in K$,子帧 $n-k$ 对应于服务小区 $c$ 的一个下行子帧或特殊子帧.此处的服务小区$c$的下行子帧或特殊子帧的判定依据为:若 UE 已为该服务小区$c$配置了高层参数
`EIMTA-MainConfigServCell-r12`,则依据高层参数 `EIMTA-MainConfigServCell-r12` 进行确定; $K$ 在表 10.1.3.1-1 中定义(该表中的 UL/DL configuration 对于应该出的 DL-reference UL/DL configuration)与子帧 $n$ 相关联.
$M_c$ 是服务小区 $c$ 中与子帧 $n$ 相关联的集合 $K_c$  中的元素个数.

在本子条款的后续部分中,$K=K_c$.

如果 UE 为 PCC 配置了参数 `EIMTA-MainConfigServCell-r12` ,则本子条款后续部分中的 "PCC 的 UL/DL configuration 就代表 PCC 的 DL-reference UL/DL configuration.
:::note
这里先不纠结,从协议上理解无论是否配置 `EIMTA-MainConfigServCell-r12`PCC 的 UL/DL configuration 和 PCC 的 DL-reference UL/DL configuration 是相等的.

当配置了 PUCCH format 3 用于传输 HARQ-ACK 时,对于服务小区中具有正常下行 CP 的特殊子帧配置 0 和 5,或具有扩展下行 CP 的特殊子帧配置 0 和 4(见 36.211 表 4.2-1),该服务小区的特殊子帧不计入 HARQ-ACK 码本大小的确定.在这种情况下,如果服务小区是主小区,则该特殊子帧中没有指示下行 SPS 释放的 PDCCH/EPDCCH.
:::note
在上面描述的几种场景种,由于特殊子帧 DwPTS 部分很短,不发送 PDSCH,所以也不存在对应 PDSCH 的反馈,另外规定在这些特殊子帧的 PDCCH 上也不能发送用于 SPS 释放的 PDCCH,所以这些子帧上就不存在 HARQ-ACK 反馈.
:::

如果服务小区的 UL-reference UL/DL configuration(定义于第 8.0 节)属于\{1,2,3,4,5,6\} 则 $W_{DAI}^{UL}$ 值由与服务小区上 PUSCH 相对应的 DCI format 0/4 中的下行分配索引(DAI)根据表 7.3-Z 在子帧 $n-k'$ 中确定,
其中 $k'$ 定义于表 7.3-Y,且表 7.3-Y 中的 TDD UL/DL Configuration 指的是该服务小区的 UL-reference UL/DL configuration(定义于子条款 8.0).
在没有 PDSCH 传输,也没有指示下行 SPS 资源释放的 PDCCH/EPDCCH 发送给 UE 的情况下,UE 可以预期如果 DCI format 0/4 被发送,则其中的 DAI 值会将被设置为 4.

:::note
为什么是 \{1,2,3,4,5,6\} 剔除了配比 0 我理解是 $W_{DAI}^{UL}$ 没有啥参考意义,但是为什么没有剔除 \{6\}, 它和 0 一样都是一对一的反馈.
没有开启上行 CA 并且支持跨载波调度的情况下服务小区的 UL-reference UL/DL configuration 就是自身的 UL/DL configuration.
:::

如果 DL-reference UL/DL configuration 属于\{1,2,3,4,5,6\},则 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D 中的 DAI 值表示在每个配置的服务小区的子帧 $n-k$ 其中$k \in k$ 内,
直至当前子帧为止,带有分配 PDSCH 传输的 PDCCH/EPDCCH 以及指示下行 SPS 释放的 PDCCH/EPDCCH 的累积数量,并且该值应逐子帧更新.将 $V_{DAI,c}^{DL}$ 表示为 UE 在服务小区 $C$ 的子帧 $n-k_m$ 中根据表 7.3-X 
检测到的带有 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D 的 PDCCH/EPDCCH 中的 DAI 值,其中 $k_m$ 是集合 $KK 中的最小值,使得 UE 在该子帧检测到一个 DCI format 1/1A/1B/1D/2/2A/2B/2C/2D.
:::note
$V_{DAI,c}^{DL}$ 中不包含 SPS 的 PDSCH,即不包含无 PDCCH 的 PDSCH.
:::

- 对于帧结构类型 1 的服务小区,若配置 PUCCH format 3 用于传输 HARQ-ACK,且对于基于检测到 DCI format 0/4 的 PDCCH/EPDCCH 调整的子帧 $n$ 中的 PUSCH 传输,UE 应假设该服务小区的 UL-reference UL/DL configuration 属于 \{1,2,3,4,5,6\}.

- 对于帧结构类型 1 的服务小区,若各服务小区的 DL-reference UL/DL configuration 均属于 \{0,1,2,3,4,6\},且配置带信道选择的 PUCCH format 1b 用于传输 HARQ-ACK 并有两个已配置服务小区时,UE 应假设该服务小区的 UL-reference UL/DL configuration 属于 \{1,2,3,4,6\}.

- 对于帧结构类型 1 的服务小区,$W_{DAI}^{UL}$ 值由子帧 $n - k'$ (其中 $ k' = 4 $) 中与该服务小区上 PUSCH 对应的 DCI format 0/4 内的下行分配索引(DAI)根据 Table 7.3-Z  <FigureRef id="36.213 Table 7.3-Z" /> 确定.

- 对于帧结构类型 1 的服务小区,当配置 PUCCH format 3 用于传输 HARQ-ACK 时,若服务小区的 DL-reference UL/DL configuration 为 0,则载波 $c$ 子帧 $n - k$ 中带对应 PDCCH/EPDCCH 的 PDSCH 传输的 HARQ-ACK 反馈,如果是单 TB TM 模式或应用 spatial HARQ-ACK bundling,关联到 $o_{c,2DAI(k)-1}^{ACK}$,否则关联到 $o_{c,2DAI(k)-2}^{ACK}$ 和 $o_{c,DAI(k)-1}^{ACK}$,其中 $DAI(k)$ 为子帧 $n - k$ 中检测到的 DCI format 1A/1B/1D/1/2/2A/2B/2C/2D 内的 DAI 值, $o_{c,2DAI(k)-2}^{ACK}$ 和 $o_{c,2DAI(k)-1}^{ACK}$ 分别为 TB 0 和 TB 1 的 HARQ-ACK 反馈.
当 $N_{SPS} > 0$ 时,无对应 PDCCH/EPDCCH 的 PDSCH 传输的 HARQ-ACK 映射到 $o_{c,O_c^{ACK}-1}^{ACK}$.未检测到 PDSCH 传输的 HARQ-ACK 反馈比特设置为 NACK.
