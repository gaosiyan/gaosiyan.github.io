7.3.1 FDD HARQ-ACK 上报流程​

对于采用 PUCCH format 1a/1b 传输的 FDD,当 HARQ-ACK 和 SR 在同一子帧中传输时,UE 应在负 SR 传输时在其分配的 HARQ-ACK PUCCH format 1a/1b 资源上传输 HARQ-ACK,并在正 SR 传输时在其分配的 SR PUCCH 资源上传输 HARQ-ACK.

对于采用带信道选择的 PUCCH format 1b 的 FDD,当 HARQ-ACK 和 SR 在同一子帧中传输时,UE 应在负 SR 传输时在其分配的带信道选择的 HARQ-ACK PUCCH 资源上(如子条款 10.1.2.2.1 所定义)传输 HARQ-ACK,并在正 SR 传输时在其分配的 SR PUCCH 资源上为每个服务小区传输一个 HARQ-ACK 比特,具体如下:

  • 如果在一个服务小区上仅检测到一个 TB 或一个指示下行 SPS 释放的 PDCCH/EPDCCH,则该服务小区的 HARQ-ACK 比特是对应于该传输块或指示下行 SPS 释放的 PDCCH/EPDCCH 的 HARQ-ACK 比特;

  • 如果在一个服务小区上接收到两个 TB,则该服务小区的 HARQ-ACK 比特是通过对对应于传输块的 HARQ-ACK 比特进行空间捆绑生成的;

  • 如果对于一个服务小区,既未检测到需要提供 HARQ-ACK 响应的 PDSCH 传输,也未检测到指示下行 SPS 释放的 PDCCH/EPDCCH,则该服务小区的 HARQ-ACK 比特设置为 NACK;

且主小区和辅小区的 HARQ-ACK 比特分别映射到 b(0)b(0)b(0) 和 b(1)b(1)b(1),其中 b(0)b(0)b(0) 和 b(1)b(1)b(1) 在 36.211 的子条款 5.4.1 中规定.

对于 FDD,当 HARQ-ACK 的 PUCCH format 3 传输与高层为 UE 配置的用于传输 SR 的子帧重合时,UE 应按照 36.212 的子条款 5.2.3.1 中的定义在 HARQ-ACK PUCCH 资源上复用 HARQ-ACK 和 SR 比特,除非 HARQ-ACK 对应于仅在 PCC 上的 PDSCH 传输或仅在 PCC 上指示下行 SPS 释放的 PDCCH/EPDCCH,在这种情况下,SR 应按照采用 PUCCH format 1a/1b 的 FDD 方式进行传输.

对于 FDD 和 PUSCH 传输,如果 UE 在子帧 n−4n-4n−4 中没有接收到 PDSCH 或指示下行 SPS 释放的 PDCCH,则 UE 不应在子帧 nnn 的 PUSCH 上传输 HARQ-ACK.

当仅传输正 SR 时,UE 应使用 36.211 的子条款 5.4.1 中定义的 SR 资源的 PUCCH format 1.
